# React Native Library Architecture

Adapted from the `react-native-android-navigation-mode` library skill for a published Android + iOS TurboModule. Repository source wins over this summary; read the files before assuming behavior.

For non-trivial changes, present approach, scope, and material decisions (public API, error codes, defaults, native minimums, ML Kit versions, new dependencies) before implementation. Existing user approval covers the agreed scope. A plan in `docs/superpowers/plans/` records approved decisions and execution limits for its tasks; read it when the task belongs to it.

The layer map below is the current structure. When an authorized change adds layers, update this skill and `AGENTS.md` in the same task.

## Contracts kept in sync

- Every fixed set of public string values is an enum constant: a frozen object with UPPER_SNAKE_CASE keys in `src/`, a `declare const` with literal values plus a same-name type in `src/index.d.ts`, a section in `docs/api-reference.md`, and cases in `type-tests/`. Plain strings stay accepted; library code, docs, and examples use the constants.
- Error codes exist in `TranslationErrorCode` (`src/translation-error.js`), `src/index.d.ts`, the Kotlin companion object, the `.mm` constants, `docs/api-reference.md`, and `type-tests/`. Change them together.
- `TranslateLanguage` in `src/languages.js` and `src/index.d.ts` (names and codes) matches ML Kit's `TranslateLanguage.getAllLanguages()` / `MLKTranslateAllLanguages()` for the pinned SDK versions.
- Native module name `MLKitTranslation` (Kotlin `NAME`, `RCT_EXPORT_MODULE`, `modulesProvider`) must match `TurboModuleRegistry.get` in the spec.
- Method signatures in the spec, the Kotlin module (`Promise` last; booleans are `Boolean`) and the `.mm` selectors (`resolve:reject:`) must match what Codegen generates.
- Kotlin package `com.reactnativemlkittranslation`, Gradle `namespace`, `codegenJavaPackageName`, `codegenConfig.android.javaPackageName`, and `react-native.config.js` must agree.
- Every JS export has a declaration in `src/index.d.ts`, a place in the grouped README API table, and a section in `docs/api-reference.md`.
- Files that must ship are listed in `package.json` `files`; `.agents/`, `.claude/`, docs, tests, tool configs, `example/`, and local config stay out of the tarball.

## JS behavior rules

- Importing the package never touches native code; a missing module rejects `NATIVE_UNAVAILABLE` per call.
- Compare and pass values through the constants (`TranslationErrorCode.ABORTED`, `ModelStatus.FAILED`, `TranslateLanguage.ENGLISH`), not string literals.
- Validation happens before queueing: empty/whitespace text `INVALID_INPUT`, unknown code `UNSUPPORTED_LANGUAGE`, `from === to` returns the text. Text is never modified, logged, cached, or persisted.
- `translate` and `prepareTranslator` go through the queue; downloads (`downloadModel`, `downloadModels`) never do and never block translations. `releaseTranslator` and `deleteModel` are barriers. `downloadModels` validates every code before starting and rejects with the first failure after all settle.
- Abort of a running request rejects the caller immediately, but the slot stays busy until native settles. Do not add JS timeouts that free the slot.
- Downloads are shared per language with the first caller's `wifiOnly`; failures clear the in-flight entry so the next call retries. No automatic retry loop.
- Model state objects are frozen and replaced only on change, so `useSyncExternalStore` snapshots stay stable.
- Keep `src/*.js` free of syntax a host Metro/Babel setup for React Native 0.76+ cannot handle.

## Native rules

- New Architecture only. Keep the module lazy (no ML Kit work at package creation or import).
- One translator at a time; same pair reused, another pair closes/drops the old one first; release waits for the running translation.
- Do not block the main/UI thread; Android may block only its own translation thread. Model-presence checks before translate/prepare share a 10-second monotonic budget via timed `Tasks.await`; timeout rejects `MODEL_MANAGER_FAILED` before translator acquisition. Queue wait, translator creation, warm-up and translation are excluded. Recheck invalidation before acquiring the translator.
- `translate` and `prepareTranslator` check models and reject `MODEL_NOT_DOWNLOADED`; they never call `downloadModelIfNeeded`. ML Kit loads models on the first translation, so `prepareTranslator` runs a short warm-up translation and drops the result.
- iOS downloads go through a background `URLSession`; verify iOS downloads with a signed build (ad-hoc is enough on the simulator).
- iOS download observers are registered before `downloadModel:conditions:`, filter by model, settle every waiter once, and are removed on invalidate/dealloc.
- Use `safeExtGet` for SDK values. Raising `minSdkVersion`, the iOS deployment target, Java/Kotlin targets, ML Kit versions, or `peerDependencies` is a public change.

## Search before creation

Before adding a helper, constant, or file, check `src/index.js`, the existing modules in `src/`, the Kotlin companion object, and the `.mm` constants. Keep the library small: no new folders or abstractions for a single function.

## Verification

Run `npm test -- --runInBand`, `npm run lint`, and `npm run typecheck`, plus the no-install checks listed in `post-task-finishing-pass`. Installing dependencies, generating fixtures, `pod install`, compiling Kotlin/Objective-C++, or running on a device/simulator requires user authorization per `AGENTS.md`. Report what was actually run; native behavior is unverified until it runs on a device.
